# SME-0001: Standard Envelope Correspondence Protocol

Status: Proposed Standard  
Version: 0.1  
Committee: Standard Envelope Working Group

## 1. Abstract

This document specifies the procedures required to transfer one value between two parties who already share an address space but have chosen to involve paperwork.

## 2. Terminology

An **envelope** is a value accompanied by a reason that the recipient cannot immediately access it.

A **recipient** is an exact, case-sensitive string. Organizational restructuring is therefore a breaking change.

An **approval** is a nonempty approver name recorded on sealed correspondence. Authenticity is outside this protocol.

A **seal** freezes routing configuration. It does not deep-freeze the payload or the sender's opinions.

## 3. Normative procedures

1. An envelope MUST begin in Draft state.
2. A sender MUST supply a nonblank recipient before sealing.
3. Draft configuration MUST become immutable after sealing.
4. Opening MUST verify recipient, clearance and requested approval before delivering a value.
5. Failed checks MUST leave the envelope sealed.
6. Successful opening MUST transition to Opened and MUST NOT deliver again.
7. ReturnToSender MUST transition sealed correspondence to Returned without delivering the payload.
8. Callers MUST serialize access to each envelope. Concurrent operation is outside this standard.

Approving correspondence without an approval requirement is permitted. Management may contribute voluntarily.

## 4. Borow extension

The optional extension MUST use an upstream BorowRef rather than simulate its metadata.

Snapshot correspondence captures the value at envelope creation. Live correspondence reads the Borow reference at opening. OriginalIntent correspondence reads the current value and compares it against an explicitly declared expected value. An inequality MUST produce ENV409 and MUST preserve Sealed state.

No inference of intention is specified. Generic equality follows EqualityComparer<T>.Default. Snapshot and declared intent retain ordinary C# value/reference semantics.

Copies of the ref struct MUST share delivery state. A photocopy is not a second envelope.

## 5. Security considerations

This library models procedure using caller-supplied strings and enums. It provides neither identity verification nor encryption. Clearance.PrincipalEnvelopeArchitect is an enum member, not an authorization credential.

## 6. Proof of delivery

If Open returns a value, a value has been returned.
